# Actions 下载产物保留策略

普通 PR 只编译并执行代码、契约和离线链路检查，不生成安装包、测试 ZIP 或更新包，也不上传 Actions 附件。固定项目的检查结果保存在作业摘要，完整日志仍由 Actions 保存。摘要不会复制步骤输出、凭据或本地运行数据。

达到一个阶段性稳定版本后，手动运行 `Rust isolated prototypes` 并明确开启 `stage_acceptance`（默认关闭），才会准备完整数据、打包并验证安装回滚及完整桌面。附件选项本身不能触发打包：

| artifacts | 下载内容 | 保留时间 |
| --- | --- | --- |
| none（默认） | 不保留下载附件；是否打包由阶段验收开关决定 | — |
| preview | 测试 ZIP 与校验文件 | 3 天 |
| full | ZIP、更新包、诊断工具、脱敏报告和测试窗口图片 | 包和工具 3 天，诊断 7 天 |

手动工作流入口需要工作流已存在于默认分支；分支上的策略须合并后才能作为仓库默认流程使用。此前可通过 PR 自动验证。

Electron 普通 PR 运行 `npm run build`，不运行 `npm run pack`。仅明确开启 `stage_acceptance` 或推送正式 `v*` 标签时，才构建安装包并进行完整窗口验证。手动验收按需启用 `upload_artifacts`，安装包保留 3 天，窗口诊断保留 7 天。正式标签通过所有检查后继续直接发布到 Releases，不额外保存 Actions 安装包副本。构建缓存不受此策略影响。

阶段验收未执行时，摘要如实显示跳过，不能据此宣布安装和界面验收通过。达到阶段目标再生成测试包；确认该阶段稳定、完成发布检查后才发布正式安装包。修改发布相关代码时可提前执行针对性检查，不默认触发全量打包。

清理旧 Actions 附件不会删除 Releases。后续清理应先列出候选产物并保留需要复核的成功包和失败证据；不以删除整个运行记录代替附件清理。已有附件的期限不会随工作流修改追溯变更。

删除后的用量可能需要 6–12 小时刷新；累计计费用量也可能继续影响本周期额度。无附件的 PR 通过只能证明验证链路通过，不能证明上传额度已经恢复。不要为探测额度反复上传大包。
