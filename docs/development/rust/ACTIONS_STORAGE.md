# Actions 下载产物保留策略

普通 PR 继续编译、测试、打包和验证安装回滚，但不上传 Actions 附件。固定项目的检查结果保存在作业摘要，完整日志仍由 Actions 保存。摘要不会复制步骤输出、凭据或本地运行数据。

需要下载 Rust 测试包时，在包含本工作流的分支手动运行 `Rust isolated prototypes`：

| artifacts | 下载内容 | 保留时间 |
| --- | --- | --- |
| none | 仅验证，无附件 | — |
| preview（默认） | 测试 ZIP 与校验文件 | 3 天 |
| full | ZIP、更新包、诊断工具、脱敏报告和测试窗口图片 | 包和工具 3 天，诊断 7 天 |

手动工作流入口需要工作流已存在于默认分支；分支上的策略须合并后才能作为仓库默认流程使用。此前可通过 PR 自动验证。

Electron 手动构建默认不保存附件，按需启用 `upload_artifacts`，安装包保留 3 天，窗口诊断保留 7 天。正式 `v*` 标签继续直接发布到 Releases，不再额外保存一份 Actions 安装包副本。构建缓存不受此策略影响。

清理旧 Actions 附件不会删除 Releases。后续清理应先列出候选产物并保留需要复核的成功包和失败证据；不以删除整个运行记录代替附件清理。已有附件的期限不会随工作流修改追溯变更。

删除后的用量可能需要 6–12 小时刷新；累计计费用量也可能继续影响本周期额度。无附件的 PR 通过只能证明验证链路通过，不能证明上传额度已经恢复。不要为探测额度反复上传大包。
