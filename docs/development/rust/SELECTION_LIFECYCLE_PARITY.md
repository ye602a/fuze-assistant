范围：继续对照 v0.6.3，补 #81 屏幕采集恢复之后的生产生命周期遗漏。保留用户正在测试的 ade18a9009b0 包，本轮不打包、不安装、不替换稳定版。

## 连续验收

`lifecycle_review.rs` 只在显式 `--review-capture lifecycle` / `lifecycle-minimal` 入口运行；生产 `tick` 始终使用真实输入。验收向同一个控制器提供固定阶段、等级和离线图像，不启动发现线程、Live Client 请求、游戏窗口采集、个人记录或图标下载。

链路：生产 Controller → ScreenCapture 策略 → GPU 裁剪的离线标题图集 → 常驻真实 ONNX → Session/Retention → Publisher → 生产 Manager → 隐藏的 Direct2D 三卡窗口。只替换外部输入，不编造 OCR 结果。连续覆盖：

1. 无英雄 ID 的 Loading 预热，不截图；InProgress 1 级低频探测不启动持久流。
2. 进入首轮阈值恢复持久流，三卡名称到达原生窗口；无英雄时不泄漏全局统计。
3. 中右遮挡短暂保留；停止供帧后仍按期清空；等级未知仍可重新识别。
4. 刷新为不同左卡，不混入旧中右卡；属性碎片隐藏正式推荐，后续正式选择恢复。
5. 英雄信息到达后切换新上下文；分别验证完整英雄统计与只有识别字典两种资源条件。
6. 后续等级继续交付，但不推断领取；赛后、下一局、暂停和所有本次 OCR 子进程退出。

`synthetic-shard-titles.png` 是本地绘制的三个中文属性标题（攻击力、法术强度、生命值），不是玩家截图。冻结成图片避免 CI 字体安装差异；其他输入使用已有仓库 OCR 样例。测试统计为刻意冲突的全局 99% 与英雄 60%/12%，均不进入玩家数据。

局部检查包括数据、门禁/Session、屏幕回退、控制器和过期结果边界；不扩大到无关功能回归。实际屏幕采集仅在自有窗口覆盖的 Windows CI 上执行。本机仅处理离线素材和隐藏窗口，渲染图片、测试输出均留在忽略目录，不上传私人日志。

本机结果（2026-10-17）：正常 GPU Release 构建通过，35 项针对性检查通过。正常流链路完成 9 次交付；两组完整生命周期各 59 次 UI 更新、16 次隐藏原生窗口绘制，首轮阈值到交付均为 486 ms。无英雄、缺统计、遮挡到期、刷新、碎片转换、后续等级、下一局隔离与本次启动的所有 OCR 子进程退出均通过。缺统计用例明确验证三卡没有借用全局 99% 数据；完整用例交付英雄统计。

边界：离线阈值到交付耗时不是实际游戏弹窗延迟。不能证明其他电脑、独占全屏、跨屏或正在测试的旧包已经通过；这些仍以玩家实测为准。仅有识别数据时不会逐帧下载或读盘，统计恢复需英雄上下文变化、重新开始识别或完成已有数据更新流程。
