# 第二批：历史表现、本组选择与组合路线

2026-11-14，源码实现；接续第一批来源排名、四阶段直显和潘朵拉转换修复。
正式版本是否包含这些修改，以合并提交及发布回执为准。

## 玩家要解决的问题

英雄平均胜率回答的是这个英雄在来源样本中的整体历史表现；单强化胜率回答的是
带有该强化的历史样本表现。两者不是随机分组的试验，也不是“选它就增加多少胜率”。
三张都低于英雄均值时，仍可能有一张更值得优先选择。

卡面因此分开显示：

- **历史表现**：原始胜率、与同批次英雄均值的百分点差、样本及单项近似抽样区间。
- **本组选择**：本组优先、可选、依赖搭配、当前不建议或证据不足，并给出实际采用的理由。
- **阶段参考**：四次选择分别显示真实胜率与场次，标明资料不全、支持不足、一致或反转。
- **组合参考**：已成立的搭配、尚缺前置的后续路线，或明确的数据缺失状态。
- **机制提示**：少量可追溯到资源说明的条件提醒，不充当组合胜率或新的推荐分。

金框只消费统一的 `Decision::Preferred`。它不再独立寻找最大旧分数，避免理由和金框指向不同卡。
卡位始终跟随识别位置，不通过重新排列卡片表达优先级。

## 英雄参考与数据口径

`decision_evidence::HistoryContext` 来自与 cards、scores 相同的 `Prepared` 英雄分片。
英雄均值只读该分片的 `champions[id].champion.stats`，不借用全局英雄目录，不用强化条目平均重建。
胜率 source、patch、dataDate 和 region 一致才生成差值；已知不一致或必要元数据缺失时显示不可比较。
同一 ARAMKit 分片中地区均为“地区未标明”时，允许描述性差值，界面仍不声称地区已核实。

腾讯补充只更新其排名元数据。胜率范围优先沿用 `winRateSource / winRateGamePatch /
winRateRegion / winRateDate`，不把腾讯排名日期或榜单条目数当作胜率日期或样本数。
缺少英雄参考不会删掉强化自身的真实胜率和来源范围。

### 显示政策与比较政策分开

| 用途 | 当前规则 | 含义 |
| --- | --- | --- |
| 高于／接近／低于英雄 | 差值在 ±1 个百分点内标接近 | 展示分档，不是等效性检验，不改源分 |
| 少样本标记 | 少于 200 场 | 保留真实胜率和场次，附少样本提示 |
| 无样本数 | 明示未提供 | 不补造胜场、区间或情境胜负关系 |
| 单项区间 | 约 95% Wilson 抽样区间 | 针对该条 reported rate，不是英雄差值的区间 |
| 情境比较 | 两边至少 500 场、差至少 2pp、单项区间不重叠 | 产品保守门槛，不声称推荐有 95% 正确率 |

区间直接使用来源四舍五入后的比例及真实场次，不把 `round(p × n)` 冒充胜场。
公式依据 [NIST 的 Wilson 区间说明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。
区间只描述简化抽样模型内的不确定性，不能处理重复玩家、选择偏差、幸存者偏差或混合人群。
英雄总体包含强化子集；本实现没有对它们进行独立双样本显著性检验。

## 统一选择规则

`contextual_advice` 是无 IO 的纯数据模块，输入三个候选及已验证可比的历史条目。
它不接收英雄均值，因此“低于英雄均值”不能直接变成 `NotAdvised`。
没有情境依据时保留第一批修复后的来源分语义，不另算胜率加权推荐分。

对每一对候选，按以下顺序取得**这一对**的比较方向：

1. 当前已确认拥有相同前置的组合，满足上述样本、差值及区间要求。
2. 四个阶段逐一均满足要求，而且四次方向一致。
3. 两边都有有效来源分，沿用来源分的相对顺序。
4. 否则这对不可比较；分数缺失不等于同分，单独一条高胜率也不补出比较。

组合只在规范化后完全相同的前置集合之间比较，例如 A+X 与 B+X。
A+X 对 B+Y 没有共同条件，不能直接排名；不同组合组也不能连成 A→B→C 后
凭传递性认定 A 胜过未直接比较的 C。

**本组优先必须同时满足：三个普通候选完整且身份互不重复；该候选分别有直接方向支持胜过另外两张。**
只有首选对某张卡的直接阶段或组合优势，才允许把那张卡标为“当前不建议”。
来源排名较低本身仍显示“可选”。因此“不建议”始终针对当前这组的已支持替代方案，不是永久黑名单。

同一对候选在不同共同前置下给出相反的强方向，或组合／阶段／来源方向形成排序环时，
整组退回原有来源顺序，解释为情境证据冲突，清除情境“不建议”。不平均互相重叠的组合样本，
不挑最高胜率规避冲突。没有整体排序证据也没有足够直接比较时，不制造首选。

只有后续组合记录、没有自身或当前情境证据时显示“依赖搭配”。如果原本已有有效来源参考，
尚未成立的路线只作为附加提示，不提前改变本轮选择。

## 当前轮次仍未确认

`ActualStage` 继续是 Unknown。等级、已选数量、卡片消失、刷新和特殊额外选择都不推断当前正式轮次。
阶段优势要求全部四次都支持同一方向，才能在未知当前轮次时参与比较。
部分阶段缺失、样本不足、差距太小或区间重叠均不足以建立阶段比较方向。
已有受支持方向在不同阶段反转时，显示反转提示，不猜测玩家正在哪一段。

原始四列仍可作为参考显示；是否进入选择引擎另有来源门禁：

- 同英雄，snapshot 可用；
- 已接受 Frame 的 dataset 与 HistoryContext 身份相同；
- 当前公开补丁参考、dataset 与 snapshot 补丁一致；
- 该强化的胜率范围确为同 patch、同 dataDate 的 ARAMKit 批次。

不满足门禁的原始资料带异批次／版本提示，不影响本组顺序。旧快照超过七天后不展示数值；
已观察到的过期状态可以保留，以区别从未准备好数据。局内不新增统计下载。

## 组合不再只有“完全命中才显示”

`augment_combos::evaluate` 分别保留：

- `current`：除候选外的全部前置都在仍有效的确认 Owned 中。
- `future`：真实记录中仍缺至少一项前置；明确缺哪些，不预测它们会出现。
- 来源状态：可用／待刷新、未就绪、过期或补丁不一致。
- 匹配状态：当前命中、仅有未来路线、尚无确认前置、无对应记录、候选已拥有。

数据字段缺失或格式异常是 `None`；合法空榜单是 `Some([])`。两者不同。
旧磁盘缓存若已经把缺失写成空榜单，无法事后还原原因；下一次正常准备会使用新解析规则。

当前搭配先选更完整前置、再选更大样本；后续路线先选缺项更少、再选样本更多。
如果该行实际用于本组比较，卡面优先展示引擎返回的同一前置行，防止解释和数值错位。
其他记录计数可见，完整原始行保留在离线详情中。未来路线展示缺失成员，已拥有成员不会冒充未来目标。
长名称以成员图标／ID及数量压缩，原名称保留在详情，数值不截短为另一种统计。

所有胜率和场次逐条保留：不将 A+C 与 B+C 拼成 A+B+C，不相乘，不求“额外胜率”，
没有记录也不当作不搭配。公开英雄文件中的组合是有限榜单，不是完整配对矩阵。
这批通过更充分使用已有条目提高提示覆盖，不扩大上游覆盖的承诺。

调用层规范化 `16.22.1 / 26.22.1` 等参考串为对应资源版本，其他补丁不沿用这些规则。

| 12317 潘朵拉的盒子 | 现有强化将随机转换，原组合前置不再确定 | 提示，不预测随机结果；确认后的清空沿用第一批 |

## 接线、缓存和验证

Publisher 同步替换 cards、scores 和不可变 HistoryContext；旧 Frame Arc 保持旧状态。
UI 读取 HostOverlay 实际接受的 Frame，避免被拒绝的迟到 OCR 帧污染当前卡片证据。
历史内容、分数、有效 Owned、补丁、名称资料及快照可用性变化会重算；仅 OCR sequence
更新且内容相同则复用渲染结果，不增加周期性网络、OCR或全表解析。

核心测试覆盖四阶段一致／反转／缺失／样本不足、同前置／不同前置、未持有到已持有再清空、
相反方向、混合排序环、不可比较的传递链、缺分不等于同分、无数据／重复／未完整候选、
卡位和组合行排列不影响结果，以及上述固定真实快照。
UI 测试覆盖统一金框、历史变化刷新、缓存复用、过期与跨批次隔离、生产禁用点击仍可见，
以及多 DPI 文本边界和像素区域。
本地平台桩测试只验证真实纯逻辑模块，不替代 Windows 宿主、Direct2D 或真实游戏验收。
最终构建、Windows 测试和截图检查以本次 PR 的记录为准。
