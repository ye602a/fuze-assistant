# M5a：持续浮窗接线与自动连接基础

本阶段仍为隔离原型，不替换稳定版，不启动本机客户端探测，不访问游戏或账号。

## 已接线

显式本地数据根目录 → `fuze-data::prepare` → 固定版本词典 → FZH2 私有启动管道 → 持久 OCR worker → Session 世代检查 → 独立消息线程的同一个原生隐藏浮窗。

图像输入仍使用已提交离线图片生成的 GPU 纹理，通过既有三标题 ROI 回读和 FZA1 原始像素协议进入 OCR。每帧不重新加载词典，不进行截图编码，不计算哈希。完整真实 WGC → 推荐 UI 的生产事件循环尚未完成，不能把本阶段离线链路说成游戏内实测。

词典仅在启动时序列化一次，2 MiB 上限；CPU 回退复用同一份内存数据。worker 不再为此链路自行读取词典文件，避免宿主和 worker 读到不同数据版本。模型与字符字典仍为显式模型路径。

浮窗有独立 Win32 消息线程、容量 1 的命令队列、世代/数据版本/递增序号校验和更新确认。使用一个可复用的自有 DIB 绘图表面，事件触发绘制，无周期重绘；窗口保持隐藏和不激活。控制线程可以等待 OCR，窗口消息线程不等待 OCR。更新确认有 2 秒上限，原型线程退出尚无硬隔离取消机制。

联调覆盖同一窗口的连续更新、重复拒收、错误数据版本拒收、中间卡位缺失、结束后清空、旧结果拒收和 worker 回收。缺失卡位不会让左右槽位移位。胜率排序和正式推荐统计尚未迁入此浮窗，置信度不得当成胜率。

## 自动发现与重连

`fuze-lcu::discovery::AutoClient` 是显式调用的原生适配器，无自动启动入口。Toolhelp 仅枚举进程元数据；对 `LeagueClient.exe` 使用有限查询权限取得实际 exe 路径，从同目录读取不超过 1024 字节的 lockfile，核对 PID。保留原进程句柄，进程退出后不能将 PID 重用误当成原连接。多个可用客户端或无法可靠检查的候选会失败，不猜测连接对象。

连接成功仅依据只读 LCU 阶段接口成功响应；401、404、传输失败均清除连接与旧凭据。没有客户端时 5 秒后再发现；失败按 1、2、5、10、30 秒退避；成功时 2 秒轮询阶段，复用连接而不反复扫描进程。暂停后无定时唤醒，恢复后重新调度。

目前是 HTTP 轮询恢复，**不是 WebSocket 重连**。适配器须创建于专用后台 IO 线程，WinHTTP 仅有单操作超时，硬取消仍待完成。尚未实现命令行凭据发现、lockfile 缺失替代路径、语言/选人接口和真实国服在线验证。离线测试不会调用发现函数。

参考：[微软进程枚举接口](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-createtoolhelp32snapshot)、[进程实际路径查询](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew)。不使用进程内存读取、注入、Shell 命令行转储或管理员提权。
