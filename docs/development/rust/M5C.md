# M5c：LCU 控制线程、会话切换与游戏窗口恢复

本阶段叠加 PR #28，稳定版入口、安装和配置均不变。新增有限时开发入口 `fuze-rust-host --live-control CONFIG_JSON SECONDS`，必须显式启动，时长 1–3600 秒。CI 和本机离线验证不运行这个入口，不访问本机客户端、游戏或用户缓存。

## 接线与数据边界

- 独立 LCU 控制线程使用现有原生进程发现：LeagueClient.exe 元数据 → 同目录 lockfile → 绑定存活进程句柄 → 固定 loopback HTTPS GET。没有 shell、进程内存读取、输入模拟或 LCU 写入。当前不是命令行凭据/WMI 发现；lockfile 不可读仍明确失败，不能声称解决了所有国服环境。
- 成功时每 2 秒读取阶段；选人/加载/游戏阶段再读取 gameflow 与本机玩家的英雄信息。选人用 localPlayerCellId 精确匹配，游戏中用临时 summonerId 精确匹配队伍，仅留下英雄和内存内不输出的对局区分键。原始响应不记录；认证只存在 LCU 线程内。API 返回值有上限，不允许重定向/代理/任意端点。无匹配、歧义、阶段竞争均拒绝，不能猜其他玩家英雄。
- 仅 queue 2400、InProgress、英雄已知时创建识别会话。阶段、英雄、对局或连接变化会立即取消旧浮窗结果；新模型加载完成后再次核对修订号。未知轮次不变，仍使用整体胜率。
- 控制线程发布的是单个最新快照，不积压事件队列；超时超过 8 秒的快照不能启动/继续识别。WinHTTP 仍是每操作超时，不是硬取消；退出等待 IO 线程结束，尚无独立 LCU 子进程看门狗。当前采用轮询，未启用 WebSocket。

## 捕获与性能

游戏窗口只匹配已认证客户端目录下 `Game/League of Legends.exe` 的规范路径；要求可见大窗口且无歧义。保留只查询元数据/等待退出权限的进程句柄，逐帧复核进程存活和 HWND 归属，阻止 PID 重用。最小化或切出前台暂停取帧并隐藏浮窗，不抢前台。

捕获错误释放 stream，按 1/2/5/10/30 秒上限重新发现和建流；正常 resize 沿用已有受控重建。worker 的一次自动 CPU 回退保持有效，不因该固定恢复事件重新拉起 DML。数据/worker 的持续故障同样退避，不热循环。空闲宿主每秒轻量检查，活跃 100 ms 调度；LCU IO 不占用 OCR/UI 线程。

GPU Map 仍保留 20 ms 软等待预算。忙碌帧使用类型化 Busy 状态，丢弃旧帧、100 ms 后再尝试；连续 5 次忙碌才触发捕获重建。没有放宽 OCR 匹配，没有提高实时读回等待上限。该变化修复“短暂忙碌等同设备故障”的恢复行为，不证明前次 CI 间歇失败就是这个原因。旧离线 GPU-atlas 对照仍失败即报错，固定诊断分类继续保留。

原生推荐窗口仅有已识别卡位时显示，使用不激活窗口方式；退出、上下文变化、最小化/切出及全卡未识别时隐藏。当前仍是开发浮窗，不是最终主界面/安装版。

## 配置与验收边界

配置仅含 `bundled_data`、可选 `cache_data`、`locale`、`worker`、`ort`、`model`、`dictionary`、`backend` 的本地路径/选项。禁止未知字段，无账号/凭据字段，不创建默认配置、不迁移现有用户配置。locale 仍由显式配置提供，自动语言发现尚未接入。等级输入链路未新增，未知等级沿用保守调度，不猜实际领取轮次。

针对性离线验证覆盖身份匹配/不支持队列/阶段竞争、英雄及对局变化、断连取消旧窗口、重复快照不重启、退避上限。Windows CI 继续检验自有窗口 WGC 9 帧整链路、5 次 resize 生命周期、worker 回退和清理。游戏目标发现/附加只编译和审查，未启动实际游戏捕获；实际国服 JSON、权限、独占全屏、多屏/DPI、设备移除和长时运行仍需显式实战验收。不能称为全 Rust 迁移完成或正式可替换稳定版。
