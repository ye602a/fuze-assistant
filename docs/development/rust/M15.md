# M15 — Windows application registration and share-card icons

PR #42 was checked at head `bf13ae1d12926d013efd231a2115798cbbfab3a3`: Windows `prototypes` succeeded; the PR was unmerged and mergeable. This milestone is stacked on that branch. Electron stable remains untouched and the repository remains private.

## Implemented

- Explicit local installation registers **Fuze Rust Preview** under the current user's Windows Uninstall registry tree. Portable startup does not register an application. No elevation, startup registration or machine-wide keys are required.
- The entry includes version, installation location, icon and a quoted maintenance command. Owned entries are refreshed after version activation, rollback and launch health handling; successful launches are not failed merely by metadata-refresh failure.
- Uninstallation checks ownership before removing program files and removes only the owned registration. Unknown values, subkeys or conflicting paths are rejected. Settings, records, caches and credentials remain as documented in M14.
- Explicit installation refreshes receipt-owned launcher and maintenance executables so older installations can use the new registry cleanup. Unknown binaries are preserved. Executable replacement is atomic per file; the executable and receipt are **not** one transaction. An interruption between them can require repair and is not claimed as a seamless rollback.
- Share PNGs use the already-loaded public hero, equipment and augment icon cache. Export introduces no network fetch, game capture or recurring workload. Missing images retain placeholders. A 1200×980 layout accommodates 12 equipment and 12 augment slots with bounded two-line labels in all three locales.
- Export remains an explicit local operation. Account identity, region, game ID, timestamps and observation history are omitted. Observations are never relabelled as actual claims.

Registration field meanings follow [Microsoft's uninstall metadata documentation](https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key); FUZE is a non-MSI, per-user implementation.

## Validation boundary

Local host tests passed 36/36 before final text/layout adjustment. Registration tests use a unique temporary volatile key outside the Windows Uninstall tree, then remove it; no real application entry or stable installation is changed. Tests cover idempotence, ownership conflict and preservation of unknown values. Synthetic installation fixtures cover replacement of owned maintenance files. Share fixtures cover maximum slot counts and three locales. Synthetic PNGs are reviewed separately from real game images. Final Windows CI is the milestone-wide gate.

## What remains before a complete player test package

| Area | Remaining requirement |
| --- | --- |
| Clean Windows machine | Current ZIP requires the x64 Visual C++ runtime. Check prerequisites or provide a properly licensed bootstrap before claiming out-of-box installation. |
| Installation/release | Player acceptance of Installed apps, shortcut/uninstall flow, upgrade/rollback; publisher signing and versioned release-channel assets. CI artifacts alone do not publish an update feed. |
| Live game | Tencent discovery/reconnect, capture recovery, CPU/DirectML timing, repeated matches, partial/occluded cards, exclusive fullscreen, DPI and physical multi-monitor recovery. Isolated fixtures do not prove these. |
| Feature parity | Complete rune-page data and optional write actions remain absent. Native three-card icons still have placeholders. These are separate from the completed share-card cache layout. |
| Stage ranking | Manual stage reference exists. Automatic ranking stays overall until actual acquisition is reliably proven; levels, shards, forges and rerolls cannot establish it. |
| Online history | Region must be unambiguous; provider access and real account acceptance remain external dependencies. Failure retains cached data. |
| Public repository | Audit history, Actions, release assets and redistribution licenses after the whole migration is complete. Do not publish the repository at this milestone. |

The current result is an isolated development preview suitable for bounded testing, not a replacement for the stable installation or a claim that the entire Rust migration is finished.
