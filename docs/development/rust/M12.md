# M12: independent per-user preview installation

Stacked on PR #39 (8eea530). Stable Electron and repository visibility are unchanged.

## Implemented

`Install-local.cmd` invokes the native updater with `--install-local`. After explicit user confirmation it installs the extracted preview into `LOCALAPPDATA/FuzeRustPreview/releases`, without elevation, registry changes, automatic launch or credential access. This is a development installer path, not a signed production installer.

Only allowlisted executables, public resources and package documentation are copied into a fresh staging directory. The copied bundle passes the real offline OCR check before a version is made current. The pointer remains pending until the existing READY/HEALTHY startup handshake succeeds; previous-version rollback is retained. Failed checks leave the old pointer intact. Unknown files and partial stages are preserved, not recursively cleaned.

A fixed `Start-Fuze-Rust.cmd` and `fuze-launcher.exe` under the isolated release root remove the dependency on the original download directory. Existing launchers are retained and checked against a local receipt only during explicit installation; this is ownership/conflict detection, not publisher authentication. Existing unexpected entry points are never overwritten. A completed same-version installation skips another OCR check and file copy. No new checks run on screenshot/OCR frames.

Installation confirmation and completion messages support all three interface languages. The package README now describes the native settings/history/champion features accurately.

## Validation

30 targeted host tests passed locally, plus a release build of all host binaries. The new isolated test covers failed preflight, pending-state rejection, idempotence, previous-version retention, rollback, private-file exclusion and existing entry-point protection. Windows integration uses the actual setup path, launches the copied application with a deliberately nonexistent portable fallback, repeats installation, then exercises the existing health/start-failure rollback scenarios. Tests never use the player's install root or game interfaces.

Final Windows CI status and artifact identity are recorded on the PR.

## Remaining boundaries

- No Authenticode identity or signed production feed; no elevation or automatic runtime installation. Existing x64 Visual C++ runtime requirement remains.
- This entry does not register Start Menu shortcuts, system uninstall entries or implement a full uninstall UI. User preferences/history are preserved separately.
- Partial staging directories or conflicting launchers are reported and preserved, not silently repaired or deleted.
- Do not replace the stable app or publish the repository until full migration acceptance and history/license/privacy review.
- Real-game performance, long sessions, physical multi-monitor behavior and actual claim evidence remain unverified.
