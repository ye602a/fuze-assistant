PR #27 的最新提交 `e5ae941` 已通过 Windows CI 38673018122。本阶段叠加开发，不合并前序 PR、不切换稳定版入口。

## 宿主

`fuze-worker-host::pipeline::Pipeline` 是会话级后台控制宿主。它拥有 Session、持久 OCR worker、WGC stream 和独立线程的原生浮窗；离线 GPU Atlas 和真实 WGC `tick_wgc` 共用 `recognize`。宿主从 Loading 开始，只有调用方明确提供 InProgress 后允许捕获。

每次 tick 最多取帧和推理一次，遵循 Session 的下一次唤醒时间；没有每帧图片编码、全图 CPU 回读、词典加载或哈希。Resize 先清空旧结果并推进世代；捕获错误停止当前 stream，交由上层决定是否重新附加，不无限重试。离开对局阶段释放 stream，PostGame/Disconnected 回收 worker。关闭后的会话需要新建宿主。

取消句柄可由控制端通知窗口立即清空，并阻止取消后的结果显示。OCR 管道仍有既有超时，控制线程在返回后回收 worker；此接口不是任意阻塞系统调用的硬抢占。调用者仍需接入 LCU/关闭事件并销毁会话，不能只取消 UI 后长期保留宿主。

WGC 仍只接受本进程自有窗口，未开放游戏窗口附加或自动启动入口。本阶段是为生产入口准备的可复用宿主模块，不是已完成的全 Rust 应用。LCU 自动发现/事件循环尚未与该模块接通，稳定软件入口不变。

## 推荐数据

`Scope::Champion(id)` 在同一数据根、语言和版本下加载 augments、分片索引及当前英雄对应的一个分片。它不需要完整英雄/装备库，不扫描其他英雄分片，失败不会用其他英雄统计顶替。索引歧义、重复英雄/符文以及跨版本分片会拒绝。

读取现有正式 client-data 格式 `champions[id].augments[].stats` 的整体 winRate、pickRate、rank/total、tier 和 games。使用现有整体排名/梯度优先及旧版评分规则；三卡位置不排序挪动。显示整体胜率、选取率、数据版本和统计来源/区域/补丁，推荐进度条不再借用 OCR 置信度。缺失或超范围的比例显示未知，不猜测百分比单位，不把无胜率变成 0%。来源优先使用 winRateSource/winRateRegion/winRateGamePatch，避免把国服选取率标签错误套用到其他地区胜率。

这表示正式数据格式已接入，不表示当前远程数据源已重新下载验证。测试使用公开格式的固定合成统计，所有真实账号和本机缓存保持隔离。阶段仍为未知，只使用整体统计；分阶段统计没有自动启用。

## 验收

- 本机：相关数据测试、Rust 编译、CPU/DirectML 离线样例 → 同一宿主 → 原生隐藏浮窗；取消、部分槽位、旧结果拒收及结束清理。
- Windows CI：仅 `GITHUB_ACTIONS=true` 与 `FUZE_RUST_CI_VISIBLE=1` 同时启用时，创建自己的可见图片窗口，WGC 获取真实窗口帧 → 三 ROI → OCR → 统计浮窗。期望 3 张已提交样例各成功匹配 3 次；失败直接失败，不假报跳过成功。
- 实战游戏、多屏/DPI、设备移除、持续运行、正式来源内容与用户界面验收仍需后续完成。

下一步优先补 LCU 与宿主的完整后台事件循环、目标窗口授权及设备恢复策略，然后主界面与正式运行入口。安装更新和差分仍为后续阶段。
