## 性能比较规则

本轮记录模型初始化、预热、单帧三槽识别、进程工作集等可获得数值。少量重复只做初步观察，不给样本不足的 P99，不把识别子路径和旧版完整截图+检测流程直接比快慢。

M1 在同设备、同 provider、同 ROI、同模型、同数据下做一轮新旧对照，分别给 cold / warm / 空闲 / CPU 回退；拟定目标为识别正确率不下降、warm P95 不比同路径基线恶化超过 10%，空闲 CPU 不高于基线，资源释放后内存不持续增长。目标允许根据基线修订，但不能倒改记录宣称通过。

完整切换前必须补：不同分辨率/DPI/多屏、三种语言、完整/缺失/无选择、刷新动画、碎片与锻造器、跨局/断线/过期响应、GPU 丢失、安装与差分失败回退。实战窗口验证由用户明确启动，不能在用户玩游戏时自动进行。

如模型直接识别标题不满足 fixture，则记录失败并保留旧链路，不通过降低要求或用期望名称填充结果来“通过”。Win32 原型通过后仍要验证最终 UI 框架；不把自身离屏绘图当作游戏实测。
