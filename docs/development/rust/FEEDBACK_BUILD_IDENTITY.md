# Rust 反馈构建身份

2026-10-19。此项为源码修复，不代表已经进入公开包；当前发布身份继续以 Releases 为准。

## 字段含义

所有版本值只接受 12 位小写十六进制 revision，缺失或无效时保持未知。包身份从实际执行文件旁的 `build.json` 读取一次（最大 16 KiB，频道必须为 `rust-development-preview`），不读取工作目录、Git、受管安装指针或任意配置内容。

| 位置 | `packageRevision` | `runtimeRevision` |
| --- | --- | --- |
| 应用内导出 | 生成该报告的运行包 | 本次内存观察的运行包；不代表附带的全部历史日志 |
| 自动 Issue / 待上传报告 | 首次生成报告的包，重试时保留 | 记录该局摘要的运行包 |
| 从历史日志补传 | 执行本次恢复的包 | 仅来自历史记录；没有记录则未知 |
| 退出后脚本导出 | 导出脚本旁的包，保留原字段语义 | 顶层为 null，观察摘要本身没有运行版本证据 |
| `persistentLog.records[]` | 不适用 | 每条日志自己的运行版本；不从报告顶层补值 |

版本值是包元数据提示，不是签名或发布者身份认证。其他构建元数据、路径、自由文本与凭据不进入报告。未知值允许省略或 null；旧报告没有这两个字段仍可读取。

## 兼容与补传去重

- 新日志逐条写入运行版本，覆盖 start / state / metrics / queue-overflow / stop，避免轮转丢失启动行后失去归属。
- 读取旧日志不补写、不改原文件。恢复遇到版本变化时切开应用会话；没有起始片段的摘要继续注明不完整。
- 报告和待传队列新增可选字段；反序列化没有“填入当前版本”的默认逻辑。已有 issue 编号和不确定发送状态继续保留。
- 补传 ID 不包含 `packageRevision`。无运行版本的历史摘要保持原算法和序列化结果，旧回执继续生效；新摘要的运行版本参与身份，避免不同构建被合并。
- 同一摘要换导出包后保持同一 ID；成功回执阻止再次排队，已有 issue 使用 PATCH。不确定的 POST 必须先查回原 issue；找不到也不能再次 POST。
- 去重针对同一份可恢复摘要。日志轮转或新增记录使摘要内容变化时，不能声称仍能识别为同一场完整比赛；没有引入账号或对局标识来推测。

## 定向验证

使用隔离合成目录和 FakeApi，不读取玩家数据，不发送真实 Issue，不启动助手桌面。

本地定向验证通过 27 项：构建读取 2、持久日志 5、反馈与队列 16、Slint 反馈编码 2、PowerShell 导出集成 2。两个 Rust 工作区格式检查及提交内容隐私扫描通过；远端 CI 结果以对应 PR 为准。

- 构建读取：有效格式、缺失/损坏/超长文件、错误频道、非字符串版本；执行文件目录与其他目录分离。
- 持久日志：旧记录、新旧版本混合、轮转后的记录、非法版本，以及后台写入的起止事件。
- 报告恢复：修改前固定摘要 ID 回归、旧队列、旧回执、新导出包、缺失启动行、发送结果未知与重启后 PATCH。
- 应用内编码与退出后导出：一致的字段语义，历史日志版本不被顶层覆盖；隐私白名单与原文件不覆盖规则继续验证。
