# 英雄详情缓存与首轮识别启动复核

本次玩家在另一台电脑反馈：点击英雄后详情/出装等待明显，以及首轮强化未显示。尚未收到该电脑的脱敏诊断文件，不能把下面的源码问题直接认定为这次实战漏识别的唯一原因。

## 已确认的交付数据范围

上一测试包 `4c9832060d1d` 的中文数据版本为 16.20.1：英雄目录 173 项、英雄分片 44 个，整套中文 JSON 共 49 个文件、14,934,416 字节。全部英雄的本地详情能解析。包内文件完备不等于启动时已将全部详情准备到内存。

原路径在首次点击每个英雄时重新准备公共 JSON 与所属分片；详情缓存达到 8 项后整批清空，切换请求失效时也丢弃已完成的解析。文字/出装读取本身不等待网络；图标和外部阶段统计是独立缓存，不属于上述整库已包含的范围。

## 修正

- 启动主界面时初始化隐藏选人组件，由后台线程一次准备完整本地数据，并逐英雄生成详情缓存。玩家当前请求优先于剩余预热；每个英雄之间检查退出和新版本请求。
- 全部英雄详情保留到该窗口生命周期结束或数据身份变化，不再按 8 项整批清空。预热后释放原始 JSON，只保留详情模型。无新增下载、全盘扫描、持续定时器或每帧 IO。
- 点击结果轮询只在有请求时启动，间隔从 100 ms 改为 16 ms，接到成功/失败后立即停止。版本不匹配与过期请求不能显示旧英雄。
- 游戏窗口未就绪独立以 500 ms 重试，不再累计到 30 秒错误退避；真正的捕获/OCR 错误保留原退避。
- 加载阶段尚未提供对局编号、进入游戏后补齐时，若已认证路径、英雄和语言一致，继续使用预热模型。已知不同对局、换英雄、换路径、断开、语言变化仍使旧任务失效。没有复用任何已识别领取结果。

## 证据与边界

在开发机对上一交付包的公开数据运行 Release 基准：旧路径读取 10 个英雄合计 235.3 ms；新路径准备完整 JSON 233.2 ms，完成全部 173 个英雄详情 775.1 ms。预热后查找只读内存。这是本地数据处理耗时，不是玩家电脑、网络或游戏弹窗的响应时间。

数据测试验证准备完成后删除合成源文件，仍可读取 20 个英雄并返回第一个英雄的同一缓存对象；覆盖完整性、版本/语言隔离及异常路径。控制器测试覆盖长时间窗口等待和加载到对局的预热交接。真实 Slint 回调检查使用隐藏自有窗口，离线切换 12 个英雄再返回首个，验证详情/出装结果和轮询停止；独立报告数据回调耗时及离屏软件绘制耗时，不冒充 GPU/实机帧率。

首轮实战原因仍待测试机 `Export-feedback.cmd` 生成的脱敏 JSON：检查进入游戏后窗口等待、捕获流、首个 OCR 结果、可读卡位和浮窗准备状态。无需开启截图日志，不读取游戏内存，不要求重新打局来代替已存在的证据。实际领取轮次继续未知，推荐排序仍采用整体胜率。
