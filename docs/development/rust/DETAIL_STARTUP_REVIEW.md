# 英雄详情缓存与首轮识别启动复核

本次玩家在另一台电脑反馈：点击英雄后详情/出装等待明显，以及首轮强化未显示。随后提供的脱敏诊断指向整局游戏窗口发现失败，原先的重试/预热修正不足以解决永久找不到窗口。以下区分已验证的运行环节、源码缺口与仍未确认的测试机条件。

## 已确认的交付数据范围

上一测试包 `4c9832060d1d` 的中文数据版本为 16.20.1：英雄目录 173 项、英雄分片 44 个，整套中文 JSON 共 49 个文件、14,934,416 字节。全部英雄的本地详情能解析。包内文件完备不等于启动时已将全部详情准备到内存。

原路径在首次点击每个英雄时重新准备公共 JSON 与所属分片；详情缓存达到 8 项后整批清空，切换请求失效时也丢弃已完成的解析。文字/出装读取本身不等待网络；图标和外部阶段统计是独立缓存，不属于上述整库已包含的范围。

## 修正

- 启动主界面时初始化隐藏选人组件，由后台线程一次准备完整本地数据，并逐英雄生成详情缓存。玩家当前请求优先于剩余预热；每个英雄之间检查退出和新版本请求。
- 全部英雄详情保留到该窗口生命周期结束或数据身份变化，不再按 8 项整批清空。预热后释放原始 JSON，只保留详情模型。无新增下载、全盘扫描、持续定时器或每帧 IO。
- 点击结果轮询只在有请求时启动，间隔从 100 ms 改为 16 ms，接到成功/失败后立即停止。版本不匹配与过期请求不能显示旧英雄。
- 游戏窗口未就绪独立以 500 ms 重试，不再累计到 30 秒错误退避；真正的捕获/OCR 错误保留原退避。
- 加载阶段尚未提供对局编号、进入游戏后补齐时，若已认证路径、英雄和语言一致，继续使用预热模型。已知不同对局、换英雄、换路径、断开、语言变化仍使旧任务失效。没有复用任何已识别领取结果。
- 游戏窗口查找支持已认证客户端同目录下的 Game，以及客户端位于 LeagueClient 子目录时的同级 Game。只检查这两种已知布局，不递归扫描、按窗口标题误选或隐式扩大到桌面采集。
- 缺少安装布局、根目录不可用、路径越界、进程查询不可用、映像路径不可读、实际路径不匹配、窗口过滤、窗口歧义和枚举失败分别输出固定诊断类型；不记录路径、窗口标题、PID 或系统错误文本。
- 所有目标发现错误保留已预热 OCR。窗口尚在创建/尺寸未就绪等过滤状态按 500 ms 重试，路径和访问错误仍使用有界退避。导出器同步允许固定类型，不会把新增类型的整条状态丢掉。

## 对照稳定版发现的迁移缺口

| 环节 | v0.6.3 | 此前 Rust 包 | 影响 |
| --- | --- | --- | --- |
| 捕获入口 | 自动服务默认屏幕采集，持久流失败可回退桌面位图 | 必须先找到与已认证客户端安装路径匹配的游戏窗口 | 入口兼容性变化，不能仅凭 OCR/WGC 单项通过声称等价 |
| 安装布局 | 屏幕采集不依赖固定 Game 相对路径 | LCU 支持 LeagueClient 子目录，截图却只拼接 client_root/Game | 两模块目录契约不一致；支持的分离布局在截图入口直接返回无窗口 |
| 窗口拒绝原因 | 记录截图失败/回退 | 路径不存在、句柄查询失败、路径不匹配等合并为等待窗口 | 现有日志不足以确定测试机具体命中哪种拒绝 |
| 捕获链路测试 | Electron 截图/OCR 测试 | WGC 测试直接提供程序自有窗口句柄 | 未经过生产 target::discover，未覆盖真实目录筛选 |

旧版 source-of-truth 为 tag v0.6.3 的 src/main/auto-screenshot-service.ts、screenshot.ts、capture-stream.ts、data-loader.ts。Rust 对照为 fuze-lcu/install.rs、discovery.rs，fuze-capture/target.rs，fuze-worker-host/controller.rs、main.rs。复用了数据/模型/美术资源及部分规则，不等于完成了运行行为和回退的等价迁移。前一提交仅修复目录契约；后续已恢复生产入口的屏幕采集与位图回退，详见 [屏幕采集与整链路验收](SCREEN_CAPTURE_PARITY.md)。屏幕入口不再查询游戏进程句柄，不增加内存访问或提权。

## 证据与边界

在开发机对上一交付包的公开数据运行 Release 基准：旧路径读取 10 个英雄合计 235.3 ms；新路径准备完整 JSON 233.2 ms，完成全部 173 个英雄详情 775.1 ms。预热后查找只读内存。这是本地数据处理耗时，不是玩家电脑、网络或游戏弹窗的响应时间。

数据测试验证准备完成后删除合成源文件，仍可读取 20 个英雄并返回第一个英雄的同一缓存对象；覆盖完整性、版本/语言隔离及异常路径。控制器测试覆盖长时间窗口等待和加载到对局的预热交接。真实 Slint 回调检查使用隐藏自有窗口，离线切换 12 个英雄再返回首个，验证详情/出装结果和轮询停止；独立报告数据回调耗时及离屏软件绘制耗时，不冒充 GPU/实机帧率。

新增定向验证覆盖平铺/分离布局、双候选路径、禁止向无关祖先目录扩展、固定拒绝类型、捕获错误保留预热模型、诊断序列化与 Windows 导出器白名单。未执行真实游戏窗口枚举、截图或输入操作。实际领取轮次继续未知，推荐排序仍采用整体胜率。
