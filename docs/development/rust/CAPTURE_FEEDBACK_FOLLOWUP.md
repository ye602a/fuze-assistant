# 屏幕采集与每局自动反馈

基于 PR #82 的识别生命周期修复继续开发，保留现有测试包；本分支不发布安装包。

## 已确认的实现差异

- 测试包的屏幕流使用 WGC `CreateForMonitor`，未设置无边框权限或会话选项，会显示系统捕获指示框。生产屏幕流改为 DXGI Desktop Duplication，按主显示器寻找所属适配器，GPU 只回读三个标题 ROI。启动失败、模式切换、黑帧、持续读回失败仍使用位图回退与 60 秒恢复间隔。旋转显示器保守使用位图。一级省电门禁释放流，进入识别区间再开启；没有额外 PNG 编解码。
- 旧 `src/main/augment-title-matcher.ts` 包含标点归一、别名和错字容忍；Rust 此前只有去空格的完全匹配。现在补回常用全角 ASCII、空白与同组标点处理、已知别名，以及有长度/置信度限制的容错。等质量歧义保持未识别；不从其他卡位或全屏补齐。没有增加第二次 OCR。任意 Unicode 兼容字符的完整 NFKC 并未引入新依赖。
- 用户报告是“识别到后又消失”，尚未取得对应新报告，不能把上述差异直接认定为测试机的唯一原因。已有 2.5 秒显示保留仍受上限约束，不延长为无限显示；新增固定卡位分类用于区分下一次失败。三卡浮窗申请排除自身的桌面捕获，避免移动/展开后把推荐文字读回；此设置只针对本进程窗口，在系统不支持时不阻止推荐显示。
- 三卡窗口使用 `WS_EX_NOACTIVATE` / `SW_SHOWNOACTIVATE` / `MA_NOACTIVATE`；只在显隐实际变化时调用 ShowWindow。全局热键仅可选 Ctrl+Shift+F8、默认关闭，没有 Q/W/E/R 拦截或模拟输入。静态代码与隐藏窗口验证不能证明测试机的技能输入卡顿原因。

## 每局 GitHub 自动反馈

设置页提供独立区域，默认关闭。用户配置仅此仓库 Issues 读写的 fine-grained PAT 后开启。固定目的地为 `ye602a/fuze-assistant` Issues，按仓库可见性开放；与私有更新的 Contents 只读凭据使用不同 Windows Credential Manager 项。

- 每个已观察到的 Loading/InProgress 对局建立随机临时报告 ID。断线和暂停不当作对局结束。PostGame 生成完整赛后摘要；直接回大厅/选人标记为“离开对局”，不伪称结算成功。中途启动与助手退出均明确标记记录不完整。
- 没有故障也会赛后上传。首次明确管线故障或部分卡位未匹配时提前提交一次，赛后 PATCH 同一 Issue，避免按帧刷屏。
- 只上传类型白名单：固定连接/采集/OCR/门禁错误、三个卡位的 empty/low-confidence/no-catalog/ambiguous/exact/alias/fuzzy/stat-shard 分类、相对耗时、计数、现有助手+OCR 子进程 CPU/内存采样。保留首次故障和最近 48 个状态，最多约 60 KB 一次请求。CPU 值按全部逻辑核归一，不等于游戏帧时间；分析耗时不是弹窗出现后的等待时间。
- 不上传原始日志、截图、OCR 原文、英雄选择、召唤师/区服/账号、对局 ID、文件路径、认证 URL 或令牌。实际领取轮次仍未知，推荐仍使用整体胜率。
- 独立后台线程与持久化待传队列，最多 32 局；OCR 不等待网络。明确断网/HTTP 拒绝可重试；请求结果不确定时先按随机报告 ID 查询，未确认之前不盲目重复 POST。异常报告不阻塞后续对局队列。队列满/目录故障会显示错误，可用已有手动导出。
- 关闭后停止新增报告和后续上传，已经发出的 HTTP 请求可能完成；本地待传摘要保留。删除上传令牌同时请求关闭。禁用不等于删除 GitHub 已有 Issue。

未启用时不读取凭据或发送网络请求。凭据配置只由用户点击触发，不在游戏阶段自动弹窗。上传结果须以界面报告编号为准；源码和离线测试不是实际 GitHub 写入成功证据。

## 验证范围

针对状态机、跨局计数、隐私白名单、排队/恢复、标题匹配做定向测试。完整离线链路仍通过真实 ONNX、GPU ROI 输入和隐藏生产三卡窗口；真实 DXGI/GDI 屏幕读取仅在 CI 自有全屏样例上运行。设置页只渲染本进程隐藏组件，不操作鼠标、键盘、游戏或真实桌面。

另机仍需验证：黄色边框是否消失、真实游戏不同显示模式的捕获、忽隐忽现对应的状态、输入卡顿与助手负载的相关性，以及用户首次配置令牌后的真实 GitHub 上传。当前分支未替换用户手上的测试包。
