## 数据和机制

ARAMKit 本次查询的公开清单为 `16.22`，数据路径为
`data/16.22-20261106-7e589f33b466`。抽查提莫、卡莎和亚索的英雄详情，
每个文件提供 10 条 `augmentCombinations`，本次样本全部是二元组合。
卡莎 `[1004,3086]` 的原始值为 `winRate: 0.6495`、`sampleCount: 6819`。
这是该英雄使用该组合的历史胜率，接口没有选择先后、完整前置集合、
同场候选集合、事件或贴纸分层字段。

26.21 的 K/DA 可额外获得强化，HEARTSTEEL 有强化修饰，五杀摇滚提供技能强化，
命令行允许在选择时刷新到更高品质。26.22 继续调整强化数值和组合交互，
例如修复珠光护手与 escAPADe / ADAPt 的暴击交互。
因此记录的符文数量不作为固定选择轮次；技能、贴纸、装备、刷新和卡片消失也不自动加入已选集合。
不同事件不做臆测加分，旧补丁组合不套用到当前补丁。

## 自动记录来源

原有识别日志记录三张候选卡片及其变化，候选记录继续保留原含义。
`fuze-lcu/history.rs` 能解析赛后 `playerAugment1..6`，但该结果不能用于当局推荐。
现有 `stage_probe` 中的候选字段和事件名称是探测假设，并非已验证的生产接口。

本次查阅 [Riot Live Client Data 文档](https://developer.riotgames.com/docs/lol#game-client-api_live-client-data-api)，
没有找到可直接接通的海克斯已选字段；`activeplayerrunes` 描述的是常规符文页。
公开项目 [mayhem-overlay](https://github.com/zp96-cmd/mayhem-overlay/blob/57c23850cc67c7b3394666ea62f5a1ebe02d0641/src/main/main.js)
使用“近期鼠标悬停的卡片 + OCR 卡片消失”推断选择，未校验真正的选择结果。
另查阅 [aram-mayhem-tracker](https://github.com/Sygnano/aram-mayhem-tracker/blob/ecfa004fe855a2a5dfbb2c37b818039f5bc72bf1/crates/mayhem-core/src/augments.rs)，
它的 OfferTracker 记录候选显示、变化和关闭，也未提供最终已选来源。
FUZE 不复用悬停推断，也不把三张候选全部记作已选。

新的 `augment_picks` 只接受如下事件链：

1. 原有等级及商店过滤之后，被点击的普通强化卡位有本帧明确身份；已知卡位 ID 不重复，不要求其他两个标题全部可读。
2. 捕获坐标与经过进程路径验证的前台游戏窗口一致，玩家在同一卡片主体内实际按下并释放左键。
3. 随后两次新采集均明确显示选择界面已消失，间隔至少 500 ms，且距点击不超过 2 秒。

按下与释放来自 Windows 的只读鼠标通知，始终原样传递输入，不发送、阻止或模拟游戏操作。
只在本局已经识别出有效候选后启动观察线程；不保存鼠标轨迹、原始坐标或其他应用输入。
刷新按钮、收起按钮、FUZE 窗口、其他应用和注入事件不会生成领取记录。
刷新使在途旧 OCR 结果失效；被点击卡位变化或不可读、拖出、超时、黑帧和窗口切换取消待确认记录。
其他卡位的 OCR 抖动不再取消有效按下/松开。点击后、首次明确关闭之前，Partial/Uncertain 只等待后续画面，不计作关闭证据，也不接受旧卡片上的新点击；已经明确消失后再出现或变得不确定仍取消。确认期限保持点击后 2 秒，不因过渡画面延长。
关闭证据使用采集开始时刻，点击前已在途的截图不确认点击结果。确认尚未完成时，即使等级调度已经降频，也最多每 500ms 采集一次，仅检查画面、不运行 OCR、不向等级门禁提交新状态；完成或超时即回到原调度。没有新帧也会到期取消，不持续空转。暂停、断连、故障状态不会被该调度唤醒。
读取候选本身、悬停、卡片单独消失均不生成已选。

这是实际点击与画面闭合的联合观察，不是官方领取回执。
当前沿用主屏采集范围，自动记录要求游戏客户区覆盖主屏；其他窗口布局静默保留单符文统计。
漏过的选择不猜测、不追问玩家。没有捕获到自然选择过程、游戏输入通知被阻止、
额外掉落自动授予或点击后紧接新一轮卡片而没有确认间隙时，不补造记录。
暂停或 worker 重建后仅恢复同局同英雄的已确认集合，退出程序后不恢复历史对局的已选。
已选数量不传给阶段排序或固定等级门禁。

用户提供的 98 秒视频展示了“本局已有秘术冲拳 → 候选旁的组合胜率”效果，
没有连续展示从真实点击到已选记录的采集过程，因此仅作为展示需求参考。
视频及提取帧仅在本机研究目录，未加入仓库。

## 保留的组合匹配规则

`PipelineStatus.picked` 将已确认集合传到 `stage_cards`，不需要任何界面回调。
候选卡片底部左侧显示已选搭配符文的小图标，多成员时竖向排列。
右侧上方标题为“已选符文 + 当前候选”，长组合名称换行；下方同一行显示组合胜率、场次与少样本提示。
卡片高度增加 36 像素，为名称单独留出位置；其他匹配组合保留在详情中。

- 必须是同英雄，且 ARAMKit 补丁与现有公开补丁参考一致；参考未知或缓存过期时不显示组合数值。
- 组合中除候选以外的全部符文都在已选集合中，才显示该行；已拥有的候选不再作为后续搭配。
- 同时有 A+C、B+C 时分别显示；有完整 A+B+C 原始行时再显示该行。
- 卡面空间有限，优先显示匹配成员更多、其次场次更多的一行；详情保留所有原始行，不挑最高胜率。
- 直接展示来源胜率与场次，不平均、相乘、相加，不计算“提升”，不改现有推荐排序。
- 少于 200 场标注“样本较少”，不隐藏真实样本数。没有匹配组合时保留单符文统计。

## 接线与开销

`stage_reference` 在原有英雄详情下载中解析组合，复用同一份 Snapshot、磁盘缓存和 Arc。
旧缓存缺少组合字段仍可读取，下一次选人/加载预取时刷新。
上游组合缺失或格式异常不影响原有单符文、阶段统计，也不触发局内补下载。

`augment_combos` 无状态匹配，Direct2D 在原有卡面底部显示附加参考。
已选集合使用 Arc，仅新确认时变更；卡片、来源和已选未变化时复用渲染结果。
组合图标通过符文 ID 对应到本局已展示卡片的资源地址，复用现有图片缓存与异步下载。
缓存缺图时显示占位，不用其他符文代替；只有图标或参考发生变化时重建绘图资源。
不新增统计接口请求、截图流、定时轮询或生产依赖，复用既有采集帧。
独立鼠标消息线程避免 OCR 阻塞输入通知；暂停、退出和管线销毁时释放。
没有改动 OCR 分类、领取阶段、固定等级门禁或推荐评分。
