# 本地识别截图日志

正常启动时默认开启，在「偏好设置 → 帮助与反馈 → 本地识别截图」可关闭本次运行的记录；下次启动重新开启。离线检查不启用。只保存本地，不自动上传。

0.7.2 的 JSON 额外记录 worker 出错步骤、CPU 恢复前的原因与耗时，以及 DXGI 回退时的固定错误码/HRESULT。黑帧判断只涉及三个标题区域，不代表全屏黑屏；先对照 GDI，同样暗时继续使用 DXGI。普通运行日志保留原有 `failure` 分类，新增可选 `worker_failure`、`worker_cause`，旧报告仍可读取。
需要识别正在运行、已连接到受支持的对局，且游戏位于前台、覆盖主屏采样区域。切回设置后可在 30 秒内
点「标记最近画面有问题」，标记的是最近一次采样，原始采样时间不变，不会截取设置页。

「打开截图目录」进入 `%LOCALAPPDATA%/FuzeRustPreview/recognition-captures`。
每条记录为一个 JSON，有可用画面时另存同名 PNG。PNG 上排从左到右为三个标题区，下排为三个按钮区，
黑色补齐部分不是游戏画面；JSON 的 `imageLayout` 给出原屏尺寸、裁剪坐标及拼图位置。
不是全屏录像，不包含整张卡片说明或开场事件横幅，暂不能凭它确认开场事件。

## 记录内容

- 程序版本、当前运行包的 `runtimeRevision`、资料标识、原始时间和采集帧标识。开发构建没有包标识时保留空值。
- 等级（未知时为空）、调度模式与下个等级、DXGI/GDI 来源及回退原因、像素选择判断。
- `pixel-gate`：像素门禁未允许 OCR；`ocr`：进入 OCR 路径，`attempted` 表示确实提交过识别任务。
  OCR 元数据包含三槽目录匹配结果、置信度、匹配方式、标题类型、商店/画面过滤是否放行、耗时。
- 结果是否发布为可见浮窗、是否沿用保留结果。它记录发布决定，不证明屏幕上的浮窗实际可见。
- `level-or-schedule-gate`：正式识别未到时间。此时只做独立 GDI 小区域诊断，来源为 `diagnostic-bitmap`，
  不调用 OCR，不修改等级/像素门禁，不消耗正式 DXGI 流中的帧，不触发浮窗。
- 采集无帧/失败时仅有 JSON，`hasImage: false`，帧与像素证据为空；不会使用之前的截图补位。

正式识别截图直接复制该次采集已读回的标题、按钮像素，经过 OCR 后再把结果写入同一记录，不重新截图。
只在确认前台游戏覆盖主屏采样区时留图，前后台切换前后再次核对窗口元数据，不读取游戏进程内存。

## 开销与保存

开启后最多每秒采样一次，只在状态变化时保存（至少间隔 2 秒）；相同状态每 30 秒留一条。
因此不是逐帧记录，极短暂的错误仍可能漏采。最近一条留在内存供手动标记，编码和写盘在后台执行，队列最多 2 条。
整个目录达到 120 条 JSON 或 64 MiB 后停止，界面显示原因；不会自动删除旧文件。移走旧记录后，重启并重新开启。
暂停识别时停止采样；关闭截图开关会清掉内存中的最近画面，已排队写入的少量记录会完成，已有文件保留。

图片可能包含采样区中的游戏文字。请先检查 PNG，只发送相关 PNG 与同名 JSON。
现有脱敏反馈导出和 GitHub 自动反馈不读取这个目录，不会自动上传截图，也不需要配置 Key。

## 本轮验证范围

模拟像素验证 PNG/JSON 对应、手动标记时间、开关、限频、队列、容量上限、写入失败与退出排空；
Slint 设置页用内存软件渲染检查关闭、开启和容量满状态，没有创建系统窗口、访问游戏或个人日志。
真实对局的窗口发现、主屏前后台切换及具体误识别截图仍待玩家实测。
