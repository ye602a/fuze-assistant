# 强化弹窗展示政策

2026-11-15，源码实现，未发布。本文规定生产三卡弹窗的默认展示方式，覆盖
[第二批情境建议](CONTEXTUAL_AUGMENT_ADVICE.md)及
[第三批路线覆盖](COMBINATION_ROUTE_COVERAGE.md)中较早的卡面布局、文案和固定高度说明。
历史统计、情境比较、来源门禁和排序算法保持原语义；本次调整展示模型与绘制方式。

## 默认布局

卡位始终跟随游戏中的左／中／右位置，三卡对齐。深色框体先区分卡片，再通过字重、
数字大小和局部色彩表达层次，不把全部参考数据连续排成正文。

| 区域 | 默认显示 | 显示条件 |
| --- | --- | --- |
| 标题栏 | 本次强化、当前识别上下文、关闭按钮 | 已有上下文才显示对应文字 |
| 卡片标题 | 图标与强化名称 | 已识别该卡；缺图使用安静的几何占位 |
| 选择标记 | 本组优先、留意搭配或优先考虑其他卡 | 统一 `Decision` 返回对应选择；普通可选与证据不足不重复贴标签 |
| 历史表现 | 大号原始胜率、小号真实场次、胜率条 | 存在有效的自身历史胜率 |
| 英雄参考 | 英雄均值、以“个百分点”表示的差值、条上的均值刻度 | 原有可比口径已经成立 |
| 分次对比 | 对左／中／右卡、具备支持方向的次数与箭头 | 已有受支持的具体阶段对照 |
| 路线框 | 当前搭配、后续留意或跨英雄参考，以及具体伙伴名称 | 存在通过原有门禁的真实路线，最多两条 |
| 机制框 | 简短的已核实机制提醒 | 原有补丁及前置条件满足 |
| 页脚 | 一行来源、补丁、资料日期 | 可见统计与路线有完整且一致的来源范围 |

金色用于本组优先及其边框；历史数值和英雄差值保持中性色。当前搭配使用青色，
后续路线使用蓝色，跨英雄参考使用紫色，机制提醒使用棕金色。颜色配合文字与框体，
不单独承担含义。阶段箭头只说明该历史次数下的比较方向。

默认卡面不再逐项罗列单项抽样区间、四阶段全部胜率与样本表、普通“可选”状态、
重复来源段落和路线缺失说明。内部证据与离线诊断详情仍保留这些数据及原因，
不因精简卡面而修改统计计算或丢失诊断状态。

## 数字语义

**“百分点”是两个百分数相减的单位。** 强化历史胜率为 52%，英雄均值为 60% 时，
差值为 `52 − 60 = −8 个百分点`。这不是相对百分比变化；后者需再除以 60%，
得到约 −13.3%。玩家卡面使用完整中文“个百分点”，不再用 `pp` 缩写。
原有算法资料中的 `2pp` 仍表示 2 个百分点，阈值没有变化。

差值仅描述可比来源中的历史记录，不表示选择这张强化会造成同等胜率收益。
低于英雄均值仍不能直接产生“不建议”，也不因此把该卡涂红。

胜率条采用共同的 0–100% 刻度，填充长度等于该条原始胜率，竖线表示可比的英雄均值。
它不是推荐分、置信度、相对于本组三卡的归一化得分或预测胜率。没有英雄参考时，
仍可显示该强化自身的有效胜率与条，省略均值文字、差值及刻度。

场次只来自该条记录；缺少场次时省略，不写零、不补造。少于 200 场沿用“少样本”标记。
原始计数在模型中保留，较大计数可以用“万场／亿场”缩短卡面文字。未通过比较门槛的
少样本记录仍可以作为历史资料展示，不因此获得情境优势。

路线框中的胜率与样本是那条真实组合记录的历史统计，不是额外加成，不与单强化胜率
相加或相乘。跨英雄参考始终没有当前英雄的胜率、场次或推荐分。

## typed 展示模型

`rust/ui-lab/src/stage_cards.rs` 在已有证据基础上生成显式类型，
`rust/ui-lab/src/direct.rs` 按这些类型决定模块是否存在及如何绘制；生产卡面不再从
包含“暂无”“未就绪”等状态的长字符串中提取统计或拼装路线框。

| 类型或字段 | 含义与边界 |
| --- | --- |
| `HistoryDisplay.rate` | 有效的自身 `Rate`；比例保留为 0–1，缺失为 `None` |
| `HistoryDisplay.hero_rate` / `delta_points` | 经原有可比性检查的英雄均值与百分点差；不能单凭卡面数值补算跨口径差值 |
| `StageDisplay` | 明确的 `other_slot` 与四次历史比较方向；`None` 不产生箭头，也不代表当前领取阶段 |
| `RouteKind` | `Current`、`Future`、`CrossHero` 三种展示用途 |
| `RouteDisplay` | 具体伙伴 ID、压缩后的名称和可选 `Rate`；当前路线保留已有伙伴，未来路线只列尚缺伙伴 |
| `Comparison.routes` | 已观察到且可展示的路线列表，空列表不生成任何路线框 |
| `Comparison.footer` | 可共享的完整来源行；口径不全或不一致时为空，不虚构共同来源 |

跨英雄路线的 `RouteDisplay.rate` 固定为 `None`，绘制端也根据 `CrossHero` 类型禁止画
胜率和样本。它继续走独立展示路径，不进入当前英雄的 `Candidate`、`HistoryContext`、
`Decision` 或金框。

路线选择顺序沿用现有规则：本组比较实际采用的同前置记录优先，然后考虑已有当前搭配
与后续路线；第二条必须是另一条真实记录。长名称在原 ID 集合不变的前提下缩短，
多成员保留成员数量，不拼造一条更长的组合。

## 空模块完全不画

缺失、未就绪、过期、补丁不符、缺少可比参考、无对应记录等状态继续保留在内部模型和
离线详情，但默认卡面不为这些状态增加标题、框体、横线或“没有……”的解释段落。
没有有效自身胜率就省略整块历史区；没有受支持方向就省略分次对比；没有路线就省略
路线区；没有机制提醒就省略机制区。缺少单个字段时只省略该字段。

空模块既不显示假数字，也不借用其他英雄、其他补丁或全局统计填满界面。省略模块不能
绕过原有门禁：过期或不匹配的数据仍不得进入比较，缺失记录也不能被解释为“不搭配”。
未识别的卡位保留简洁的图形占位，维持左／中／右位置，不增加缺失说明正文。

## 选择、阶段与交互保持一致

金框只由与当前卡 ID 匹配的统一 `Decision` 中 `Choice::Preferred` 驱动，推荐徽标和
短理由消费同一个决定。不再单独从历史胜率、图形长度或旧分数推选金框。

情境比较继续要求原有可比批次、相同前置等约束；每边至少 500 场、差至少 2 个百分点、
单项区间不重叠等门槛不变。首选仍须分别直接优于另两张，冲突回退及未来路线不提前
加分等规则不变。完整算法以 [第二批说明](CONTEXTUAL_AUGMENT_ADVICE.md)为准。

实际领取阶段仍为 `ActualStage::Unknown`。分次对比中的 1–4 只是历史正式选择次数，
不能据等级、已选数量、消失或刷新推断当前轮次。只有完整四阶段同向证据才可按原规则
影响排序；局部方向只提供参考。上游组合仍是有限榜单，展示调整没有扩大其覆盖。

生产窗口继续只支持标题栏拖动和右上角关闭，不新增点击展开、滚轮详情或其他卡片交互。
离线诊断预览的详情交互不成为生产路径的必要步骤。局内不新增统计请求。

## 自适应高度

窗口保持 760 逻辑像素宽，卡片的共享底边取三卡实际模块所需高度的最大值；页脚存在时
才为它留空间。无历史、阶段、路线或机制模块的卡片不因占位说明撑高窗口，三卡仍保持
同一底边。高度变化继续遵循原有 DPI 缩放与原生窗口重绘路径。

同一 `stage-and-combo` 基线样例中，旧卡面为 760×440，新布局自然高度为 760×312；
其他 fixture 按实际模块变化，不能把 312 当作新的固定高度。离线展开详情保留独立的
诊断布局需求，不用它来决定生产三卡默认高度。
