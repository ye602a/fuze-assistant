# 屏幕采集与整链路验收

基准为 v0.6.3 的 auto-screenshot-service.ts、screenshot.ts、capture-stream.ts；不以原型窗口能产生帧替代生产捕获入口验收。

## 恢复的行为

| 项目 | v0.6.3 默认 | Rust 迁移 |
| --- | --- | --- |
| 源选择 | 主显示器屏幕，默认不依赖游戏窗口 | 主显示器 WGC，不调用游戏进程句柄或目录匹配 |
| 持久流 | 复用采集会话，最多 2 FPS | 复用 WGC 会话；支持时设置 500 ms 最小更新周期，宿主最多每 500 ms 处理一次屏幕帧 |
| 失败回退 | 流启动/读取超时、黑帧后使用位图 | 启动失败、首帧超时、持续无帧、黑帧和重复 GPU 忙均进入原生 GDI 位图回退 |
| 恢复 | 冷却 60 秒，再尝试持久流 | 同为 60 秒；重建期间继续用已有位图路径直到持久流真正产帧 |
| 图像处理 | RawFrame，避免重复 PNG 编解码 | 持久流仅读三卡标题 ROI；位图一次获取横跨三标题的窄条带，再裁成三卡图集 |
| 生命周期 | 暂停、阶段退出关闭会话 | 生产控制器仅在已认证、受支持 InProgress 启动；暂停/阶段退出释放采集，赛后停止工作进程并清空弹窗 |
| 可观测性 | 流/位图状态及错误 | 持久脱敏日志增加固定 capture_source、capture_fallback，成功回退不会误报 OCR 故障 |

没有 PNG 编码、整屏 CPU 像素分配、图片落盘、新增模型或新增系统依赖。位图读回复用 DIB 和输出数组，单次 BitBlt 防止三卡来自不同采样时刻。已有 OCR 标题缓存继续负责重复内容复用，不叠加新哈希校验。已支持的原生标题几何为 320–4096 × 180–2160；超出范围明确失败，不声称支持任意屏幕尺寸。

## 验收路径

生产入口 Controller -> capture_screen -> ScreenCapture -> 标题图集 -> 常驻 ONNX worker -> 数据目录/英雄推荐 -> Publisher -> 生产 Manager -> 原生三卡窗口。UI 检查在与生产相同的线程边界交付结果，使用真正 OCR 输出，不手工编造三卡快照。测试和生产共用 Config::prepare，包括独立识别字典；固定公开素材配套冻结目录用于严格检查三卡，另用随包真实数据检查实际名称和缺失统计。不能把冻结的 60% 测试统计当作玩家推荐数据。

整链路渲染检查另外发现并修复生产数据范围错误：原宿主以 Champion 范围准备数据，随后调用需要 items.json 的 champion_detail，并把错误替换为空详情，导致有识别名和评分却无胜率/选取率。改为预热时准备 Detail 范围（单英雄分片及约 168 KiB 装备目录），详情失败明确传递；没有新增逐帧读盘。验收逐卡比较完整展示数据，并要求固定三卡的胜率、选取率均到达发布帧和弹窗。

- 本机：只用仓库离线图片生成 GPU 纹理；覆盖正常流、强制启动失败、读取中途失败。通过真实模型和随包推荐数据，检查完整三卡、部分卡位、无匹配画面、弹窗绘制、赛后清空与子进程回收。该路径验证回退策略，不冒充本机桌面/GDI 采样。
- Windows CI：先在隔离虚拟机用自有窗口铺满主显示器，再调用与生产相同的真实屏幕 WGC；另一路强制流不可用，执行原生 GDI 回退。完整运行 OCR、数据匹配和生产弹窗绘制。正常屏幕项必须实际产出 screen-stream 帧，否则失败，不能以静默回退当作 WGC 通过。
- 定向回归：60 秒冷却、冷启动/运行中超时、黑帧、重建期间持续回退、固定诊断序列化、旧日志读取和导出白名单。
- 打包：完成相关 CI 后制作同提交的便携测试包，运行搬移目录检查、OCR 初始化/回收及隐藏主界面启动检查；不安装、不启动游戏、不操作系统输入。

实际国服对局、独占全屏、跨屏和 RDP 重连仍需用户测试。与 v0.6.3 默认一致，目前选主显示器；不把该默认行为声称为自动追踪任意显示器。领取轮次仍 Unknown，自动推荐保持整体胜率。
