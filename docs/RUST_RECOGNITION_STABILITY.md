# 识别稳定性：v0.6.3 路径对照

本次对照的是 Git 标签 `v0.6.3` 中的实际实现，不以迁移清单代替代码。对应旧版的 `image-analyzer.ts`、`auto-screenshot-service.ts`、`screenshot.ts` 与当前保留文件的 Git blob 一致。

| 环节 | 旧版机制 | 修复前 Rust 差异 | 本轮处理 |
| --- | --- | --- | --- |
| 标题区域 | Paddle 路径从屏高 35% 开始，取 9.5% 高、卡宽 96% 的区域 | 固定在 38.5%，只有 3% 高、卡宽 84%；标题上下移动可能被提前裁断 | 三卡统一恢复旧版取景范围；在区域内按字形行投影定位标题，仍为每卡一次识别 |
| 静态画面复用 | 完整三卡 3 秒、部分/失败 1 秒、碎片 10 秒；命中不续期 | 字节相同且会话不变就永久复用 | 恢复相同期限，保留单条精确字节比较，不增加哈希 |
| 部分识别 | 有已知卡持续匹配时不清空整个浮窗，缺位经过宽限后降级显示 | 同一 2.5 秒期限同时负责缺位宽限和整窗失效；先清空再处理新帧 | 分离缺位宽限与失去画面的期限，持续部分识别原位降级；先处理到达的新帧 |
| 刷新/碎片 | 新标题不能与旧缺位混合，碎片不进入正式推荐 | 已有同位置 ID 与碎片隔离 | 保留；本轮不根据观察推断领取 |
| 等级门禁 | 接近阈值预热、选择期间活跃、缺少等级时回退 | 当前有加载预热、阈值唤醒、等级失效回退、晚出现选择的巡检 | 保留；没有证据支持把旧版的“消失视为该等级已完成”恢复为实际领取确认 |

扩大采集范围不等于恢复旧版的全部 Paddle 文本检测模型。Rust 仍采用小区域行定位加文字识别；极端遮挡、长标题换行或超出区域的布局仍需实战样本验证。不能把离线通过视为另一台电脑的问题全部解决。

性能边界：1920×1080 的三卡 BGRA 总回读约 374 KiB，每次仍只有一张图集、每卡一次文字识别，无图片编解码、新依赖或额外截图循环。复用过期才允许重新识别；命中期限内不推理。采集源继续使用 DXGI 与位图回退。

验收使用提交过的三张截图、合成标题位移及遮挡输入，经过 GPU 区域读取、真实 ONNX 子进程、生产 Controller/发布器与隐藏原生浮窗。不得使用真实桌面、游戏接口或系统输入；领取阶段保持未知、胜率保持整体统计。验证结果记在本轮 PR，真实测试机结果另行确认。
