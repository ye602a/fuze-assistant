## 首次实战包前的集中检查

1. 完成上表必要开发缺口，核对所有堆叠 PR 的当前 CI；先做一次最终格式、编译、隐私扫描。不要用旧检查结果覆盖新提交。
2. 一次性构建功能二进制，使用已有合成数据/隔离入口验证：首页与错误状态、设置/存储/更新操作、战绩/未绑定事件与导入取消、选人阵容变化和图片回写、三卡说明及位置生命周期。新增边界需要补入同轮夹具，不使用个人数据。
3. 集中检查实际渲染；不把离屏/隐藏窗口结果写成可见窗口通过。人工中文输入、拖动与跨屏列给用户；代理不得操作鼠标或游戏。
4. 在隔离安装目录验证整个 Slint 载荷和更新/失败回滚，再进行发布前源码及产物隐私检查。确认没有阻断问题后才生成**一个**阶段测试安装包，稳定安装保持可恢复。
5. 明确通知玩家“开发侧检查通过，可开始首次实战”，附支持/未验证范围。玩家反馈前不声称真实领取轮次、实际延迟或全功能迁移完成。

## 本机必要编译命令

从实际仓库根执行已存在的隔离工具链包装器，无需重装依赖或改系统 PATH：

```powershell
& ../../work/cargo-fuze.ps1 fmt --manifest-path rust/ui-lab/Cargo.toml -- --check
& ../../work/cargo-fuze.ps1 fmt --manifest-path rust/Cargo.toml -p fuze-worker-host -- --check
& ../../work/cargo-fuze.ps1 check --manifest-path rust/ui-lab/Cargo.toml --features gpu --locked --offline -j 1
node scripts/check-secrets.mjs
git diff --check
```

每条命令检查退出码。本机完整 release 曾因优化阶段内存压力失败；开发侧功能构建可参考既有记录使用 `cargo rustc` 的低优化参数，但**不得把这种功能构建计时当成发布性能结果**。不重跑大型构建来证明已通过的静态检查。
