# 对局结束与多次运行的缓存生命周期

以下修复从 v0.5.0 起包含在正式安装包中。结束对局时释放临时状态；个人历史和可复用的公开数据有不同的保留规则。

## 保留与释放

| 内容 | 生命周期与边界 |
| --- | --- |
| 截图原始帧、待分析帧、等级门控 | 停止自动截图时清空；销毁截图窗口、取消截图定时器。旧异步结果由运行编号阻止回流。 |
| 当前三卡、推荐结果、手动隐藏标记 | 停止截图也清空并通知浮窗，覆盖未收到完整结算阶段的停止路径。 |
| OCR 模型进程 | 最后一项任务结束后空闲两分钟释放，避免短时重开反复加载；显式销毁取消正在执行和已经排队的任务。应用退出后拒绝新任务。 |
| OCR 标题结果缓存 | 一份，图像数据最多 2 MiB；失效在下一次读取时清除，分析器关闭时清空。不会逐帧或逐局累加。 |
| 推荐数据的内存缓存 | 最近使用优先：最多 256 份数据文件、256 份英雄详情、12 份强化详情表、256 份英雄强化统计。条数限制不是进程总内存的字节上限。 |
| 推荐数据的磁盘缓存 | 保留供离线读取；仅在新版本完整后激活。v0.5.0 已增加按需存储管理与清理预览，没有后台自动总容量淘汰。不会因为多开一局就生成新版本。 |
| 本人战绩 | 最多 5 个账号与区服组合，各 500 场；按对局 ID 合并。固定文件原子替换。 |
| 本地选择记录 | 最多 100 局，每局 80 次有效观察，界面按账号返回最近 20 局。结束时落盘并撤销延迟写入定时器。 |
| 赛后战绩刷新 | 结算或大厅稳定十秒后尝试一次；新选人、断开或退出取消尚未执行的任务。停止后迟到事件不能重新安排任务。 |
| 部分识别诊断截图 | 保存新截图后按现有规则保留最近 60 张；不在对局结束时清空。 |
| 日志 | 现有规则按日轮转、单文件约 5 MiB、每日 3 份、保留约七天；不是逐局日志。 |

正常写入时，临时文件经重命名成为正式文件。推荐数据写入失败时只尽力删除该次写入创建的临时文件，保留最后完整版本；成功路径不再做一次额外删除或校验。强制结束进程、断电、持续的文件权限错误仍可能留下临时文件，本轮没有扫描删除用户已有文件。战绩与选择记录使用固定临时文件名，成功写入后消失，失败重试复用该路径。

## 本轮修复及验证

- 先复现 OCR 销毁后排队的识别和预热仍会成功执行的问题，再分离显式停止与内部后端恢复。GPU 失败切换 CPU、模型空闲释放后再次使用仍正常。
- 100 次截图启停检查每次无截图定时器、帧缓存和旧推荐；旧 OCR 和窗口就绪回调不能更新下一次运行。
- 100 次 OCR 服务创建/识别/销毁检查每个模拟工作进程被释放、空闲定时器归零；应用退出后不再接受预热。
- 102 局写入穿插 10 次缓存实例重建，每局结束无写入定时器，文件只保留一份正式记录，局数上限为 100。
- 12 次账号轮换和磁盘重读验证仅保留 5 个组合，各 500 场，无临时文件堆积。
- 100 局赛后刷新每局只执行一次；停止后的迟到阶段事件不再安排刷新。
- 10,000 条跨版本内存缓存输入保持条数上限，最近使用的数据仍可复用。
- 分别模拟 30 次写入失败和 30 次重命名失败，保留原文件且不积累临时文件；解除故障后可以继续写入。

这些是隔离的状态机、模拟 OCR 工作进程、真实临时文件读写测试。另运行真实 OCR 图片回归以检查识别结果。它们不等于连续百场真实游戏测试，也不能替代实机 GPU 内存和长时间进程内存采样。

## 后续优先级

1. **存储管理**：v0.5.0 已实现按需统计与清理预览，当前完整版本、回退版本、个人战绩和选择记录分别保护。见 [存储管理说明](STORAGE_MANAGEMENT.md)。
2. **每局识别摘要**：v0.5.0 已实现，在本地选择记录中展示截图、分析、等级等待、真实 CPU/GPU 推理请求、回退事件与最近异常环节。零识别对局也保存摘要；不把零次当作故障。见 [摘要与复盘筛选](RECOGNITION_RECAP.md)。
3. **个人复盘筛选**：v0.5.0 已实现。本人战绩在最多 500 场已保存记录中先筛选再分页；本地选择记录筛选当前账号最近 20 局。缺失赛后资料单独标记，不推断选择或总体胜率。
