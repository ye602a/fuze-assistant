# 选人操作、按需图片与未绑定观察入口

> 后续已补齐未绑定完整事件/名称和三卡说明/拖动/记忆，见 [OBSERVATION_OVERLAY.md](OBSERVATION_OVERLAY.md)。本文保留本批历史验证边界。

基于 PR #55（Windows CI 已通过）继续迁移。按本轮要求只做编译、格式、差异和隐私检查，复杂运行验证留到统一验收。本批没有运行应用、调用游戏接口、打开外部攻略、配置真实装备方案或读取个人记录；没有打包、合并、替换稳定版。

## 开发内容

- 在原有五人阵容、候选网格和英雄详情结构内接入相关攻略。来源使用既有公开数据，点击时再次校验 HTTPS URL，通过默认浏览器打开，不内嵌网页，也不自动打开。
- 接通装备方案入口。仅自己的当前英雄、选人面板、非离线模式且已有方案时启用。先确认英雄和方案数量，再调用已有事务；该事务重新核对选人阶段、英雄与账号，只替换助手管理的方案并保留用户方案。英雄或数据上下文变化取消待确认操作，旧任务反馈不写入新上下文。没有添加购买装备、选择英雄或配置符文的自动操作。
- 场次指标接到实际英雄统计；缺数据继续显示未知，不填固定样例数字。
- 英雄阵容、候选、装备与强化图片复用统一的公开资源/缓存适配器。正文读取与图片解码/下载分离；先读取本地文字，图片后台补齐。移除原文字线程里批量解码整份强化图标的工作。
- 当前请求优先阵容、候选和可见范围的 24 张强化图片，再补出装图片，总引用去重后最多 96。滚动 150 ms 防抖，旧请求不回写。内存与磁盘缓存沿用既有限制，UI 复用相同图片对象的转换结果，避免每批重复转换；结果轮询在完成后停止。图标行更新保持当前强化说明和列表模型，避免补图时重置展开状态。
- 战绩页新增“查看未绑定本地观察”。只从宿主已加载记录中取得最近 8 段未绑定摘要，不重复读盘，不猜测账号或对局归属，也不混进账号战绩。缺失位置保留，达到记录上限时提示。

## 本轮检查边界

`cargo check --features gpu --locked --offline -j 1` 检查 Rust 和 Slint 编译；格式、差异、机械 UI 扫描与隐私扫描单独执行。没有执行窗口、OCR、LCU、剪贴板、性能基准或安装回滚测试，也没有生成新截图。本文件不代表视觉或运行验收通过。

针对本次堆叠 PR 的基分支 `feat/slint-history-actions`，Windows CI 仅检查格式、编译和隐私。其他已有分支的完整检查不变，手动 `workflow_dispatch` 仍跑完整流程，发布工作流不变。
