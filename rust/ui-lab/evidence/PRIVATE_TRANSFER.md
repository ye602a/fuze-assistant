# 当前 Rust 更新器：私有频道只下载复验

2026-10-16，基于 PR #62。复用已经发布的历史 Rust 载荷，不生成安装包，不安装、解包或启动下载的文件。

## 本批实现

- `fuze-update-verify --transport-private` 把真实传输验证从安装/回滚验证中拆出；两者调用同一份生产下载、差分重建及最终校验代码。原有显式安装验证入口保留。
- 验证要求基线确实包含可复用块和待下载块，避免把完全复用或整包下载算成差分成功。元数据、块图、差分和全量共用十分钟预算；同步 WinHTTP 调用仍可能延迟观察取消，外层开发脚本另有 620 秒终止上限。
- 开发脚本只允许全新的 `rust/artifacts/private-transfer-*` 输出目录。读取本机已有 Git 凭据后通过匿名管道交给验证进程；不放入参数、环境、报告或新凭据存储。报告只接受固定字段、计数、耗时与固定错误，不输出原始工具错误或认证下载地址。
- 新增可选的固定网络阶段及 WinHTTP 数字错误码；正常运行没有新增日志或轮询。数据接收计数包括失败尝试，不包含元数据及 HTTP/TLS 开销，不等同于网卡流量。
- 修复 Range 包分块被归入 45 秒元数据总时限的问题：包分块采用包传输预算，仍受调用方统一十分钟预算及原有 WinHTTP 连接/发送/接收超时约束。元数据仍为 45 秒；没有增加重试、重复校验或后台游戏任务。这可避免慢速但仍有进展的分块过早退出，不保证任意网络都会下载成功。
- Windows CI 仅跑定向更新检查和验证程序构建/脚本语法，不持有访问令牌，不执行真实下载，不生成安装包。

## 当前实测结果：部分通过，完整更新未放行

| 检查 | 结果 | 证据与边界 |
|---|---|---|
| 前置 PR #62 | 通过 | Windows run 38900861413，包含语言检查与隐藏宿主检查 |
| 本机更新定向检查 | 通过 | 10 项测试通过，验证程序编译/链接及脚本语法通过 |
| 私有频道读取与真实 Range 差分 | 通过 | 复验请求 3 个变更范围，接收 995,461 字节；重建 48,200,101 字节文件后生产最终校验通过 |
| 差分阶段耗时 | 修复前复验 58,284 ms，修复后复验 29,063 ms | 从验证开始到差分完成，包含元数据请求和本地工作；网络存在波动，不能当作单纯下载耗时或宣称修复使性能翻倍 |
| 强制全量回退，第一次 | 失败 | `update-network`；暂存文件写入 1,048,576 字节后终止。原始通用错误没有足够证据确定网络根因 |
| 强制全量回退，修复前带诊断复验 | 失败 | `update-cancelled-or-timeout`；进程退出后暂存文件为 9,437,184 字节。没有 WinHTTP 数字错误输出；代码中的分块 45 秒截止早于整体预算，未完成整包。底层网络慢的原因仍不明确 |
| 强制全量回退，修复后 | 未通过 | 差分再次完成最终校验；全量有序写入 30,408,704 字节（29 MiB），随后 `update-cancelled-or-timeout`。固定诊断明确 `scope=caller`，是统一十分钟预算结束，不是分块短时限；全量最终校验未执行成功 |
| 新 Slint 包真实在线升级 | 未测试 | 本次没有新建载荷、安装、启动、回滚或替换稳定版 |

同一目标的差分传输比整包少约 97.9% 的包数据，但**全量回退仍未通过本机当前网络验收**。本批修复分块预算后只复验一次，不为使测试通过而取消整体超时、放松校验或反复重试整包。M7A 的历史联网/安装成功证据仍保留；它不能替代本轮实际失败。

## 后续门槛

继续定位当前全量下载吞吐和请求开销，在取消、有限预算与认证隔离下改进，再复验真实完整回退。不要再次修复已经解决的 45 秒分块分类问题；也不能把失败简单归因于代理、权限或账号。私有认证和差分可用不等于安装已成功。完整 Slint 文案、可见中文输入法/跨屏和游戏共存仍按阶段交接清单推进；实际领取轮次未知，自动推荐保持整体胜率。

复验命令（显式运行，使用已经存在的历史载荷；输出目录必须尚不存在）：

```powershell
node scripts/check-rust-private-transfer.mjs <fuze-update-verify.exe> <historical.fuz> rust/artifacts/private-transfer-<unique-run>
```

失败暂存文件保留在忽略目录供本地核对；没有自动上传任何下载文件、凭据或个人记录。
