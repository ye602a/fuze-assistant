# 显式重试时续传全量包

2026-10-16；基于 PR #64，分支 `feat/rust-update-resume`。本批先复核 #64 的 Windows 更新 CI 38908962753，结果成功。

## 行为与边界

之前全量下载失败后，临时目录会被清理，下一次显式更新只能从零下载。本批在 Rust 更新器的全量路径中接入一个独立缓存文件 `download.resume`，位于受管 Rust 安装根目录；稳定版及游戏路径不变。

- 缓存头仅保存固定格式与已验证的发布清单，包含版本、序列、尺寸、摘要；没有下载地址、签名 URL、凭据或用户记录。只保留一个包，最大 512 MiB 加 4 KiB 头。
- 只有玩家再次确认下载才尝试续传，不后台重试。每次重新读取发布信息和认证，不复用上次的 CDN 地址。
- 已保留前缀仍不可信。未完成包向下对齐到 1 MiB，放弃末尾不足一块的内容；下载完成后仍由原有流程执行完整 SHA-512 校验，才可解包和安装。缓存长度不证明内容正确，也不证明安装成功。
- 更新清单变化时只重置格式正确的自有缓存。未知格式、被占用、重解析点或硬链接均不使用，保留文件并尝试普通下载。
- 续传请求不支持 Range 时，先截断缓存再从零开始一次；认证失败、取消和超时不触发这次重试。已有差分回退、单次操作 600 秒预算和四路请求上限保持。
- 超时/取消保留候选前缀；最终摘要不符时清空候选内容，避免下次反复复用坏数据。成功更新下载后，包括后续差分成功，清空已识别缓存载荷，仅保留 4 KiB 头。
- 下载窗口增加“继续上次下载 · 保留片段仍须整包校验”，支持简体、繁体、英文。复用字节不计入本次网络接收量；完整包的续传不冒充差分更新。

## 性能取舍

没有逐块哈希或每包数据刷盘；每次下载尝试结束时同步一次。四路请求与 1 MiB 分块维持不变。为了保持临时包与最终校验/安装接口不变，续传缓存完成后通过 64 KiB 缓冲复制到临时包，再执行原有一次整包校验：增加一次有界本地复制及短暂双份磁盘占用，换取跨进程失败续传。该路径仅存在于显式运行的独立更新器，不增加游戏循环、OCR 或空闲 UI 的任务。

失败时的缓存可以保留到下次显式更新；本批没有新增缓存清理按钮，卸载按现有策略保留未知/暂存文件。不能把“单文件、有上限”描述成失败后零磁盘占用。
