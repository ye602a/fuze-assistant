# Slint 图形恢复与受管启动收口

2026-10-16，基于 PR #58。该 PR 的完整 Windows CI 38882908984 已通过：优化构建、离屏/隐藏窗口、门禁与业务联调全部成功。本批继续堆叠 PR，不发布、不安装、不替换稳定版。

## 行为与边界

- 正式入口使用 Rust 启动监督进程运行一个 Slint 会话。子进程先等待匿名管道放行，加入关闭即回收的进程 Job 后才初始化界面和宿主。UI Job 只管理明确加入的会话，允许后代脱离，避免关闭攻略浏览器或文件管理器；OCR 工作进程继续由自己的严格 Job 管理。此行为遵循 [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。主入口保持原单实例互斥，子会话另有互斥。监督进程没有 OCR、LCU、图像轮询或界面，正常运行期间阻塞等管道消息。
- 图形初始化、首轮绘制或 Slint 事件循环返回错误时，先停止旧会话、等待进程结束、关闭 Job，再以 Skia 软件模式重试一次。软件模式再次失败则退出，不无限重启。普通配置/数据/宿主错误不切换渲染器；用户正常退出不重启。
- 会话已经健康运行后才发生的图形错误，恢复后强制本次启动保持暂停，不覆盖原来的自动启动偏好。用户明确继续之后才恢复识别。界面回退不修改 OCR 后端；已有三卡 Direct2D 设备资源重建逻辑保持独立。
- 恢复提示复用原中文版窗口提示条，不引入预览按钮或新的页面结构。中文、蓝金配色、五人阵容与候选网格不变。
- 健康交接在原生重绘事件之后继续观察运行状态；窗口绘制错误仍由事件循环返回处理。离线快照只作为栅格验证，不能冒充 GPU 呈现。避免常驻 `RenderingNotifier`：当前固定 Slint 1.13.1 在注册它时会禁用 Skia 局部重绘，且部分后端不触发该通知。复用已有原生事件回调，不加逐帧抓图或截图编码。
- Slint 启动器等待上限覆盖一次恢复，旧 Win32 上限不变。明确更新操作交给监督进程，在会话、Job 和互斥都释放后启动原有更新程序，防止更新进程被界面 Job 一起结束。
- 产物检查脚本按 `build.json.uiFrontend` 选择真实入口；Slint 只声明当前简体中文界面覆盖，不再用旧 Win32 的多语言检查冒充 Slint 完成。

## 开发侧验证

本轮均使用合成数据、公开资源、自有隐藏窗口和隔离目录；没有访问游戏、个人记录、原始日志或令牌，没有鼠标/键盘输入或系统安装。

`--review-recovery` 验证了启动图形失败后两次尝试成功、运行阶段注入故障后以暂停状态恢复、软件端失败终止、普通错误不重试、正常退出不重启。运行故障注入使用真实 Slint 软件后端以免 CI 依赖显卡；**这不是物理设备丢失测试**。故障开关只允许离线入口，生产入口拒绝。

已有隐藏 Skia OpenGL Surface 验证在本机实际创建 NVIDIA GeForce RTX 3060 Ti 上的上下文，并完成显式销毁/重建。1120 宽的合成画面，绘制至提交前中位约 2.65 ms；包含呈现等待与同步约 16.63 ms，空闲检查 0 次重绘。它是独立隐藏 Surface 的功能构建，不能当作正式 Winit 窗口、整机游戏负载或真实设备重置的性能结论。

本机本批最终功能构建、恢复检查、受管隐藏启动、隔离载荷检查以及 `fuze-update-verify --offline` 均退出 0。离线验证覆盖本地安装、重复启动、重复安装幂等、实际模型缺失回滚、实际启动失败回滚、隔离快捷方式与卸载。载荷按白名单收集 172 个文件；这些是忽略目录内的验收夹具，没有发布安装包。暂存源码隐私扫描 1,060 个文件无发现。功能构建仍使用低优化顶层参数规避历史本机编译内存问题，优化发布构建以 Windows CI 为准。
